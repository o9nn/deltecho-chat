# Lucy: UV-atlas-to-Cubism authoring contract and AIRI interchange

**Status (5 October 2026): artwork planning + package-validation bridge, not a rigged Lucy model.** The machine-readable [rig-manifest.json](rig-manifest.json) is a **55-target-layer specification**, not existing art. No Lucy `.moc3` or AIRI character package is shipped by this branch.

## Evidence and correct source of the art

The user-supplied `neon_angel_awe_import.psd` is 2048 × 2048 with exactly **one** visible pixel layer, `00_head_albedo` (SHA-256 `adaba232b9219be0f34f6f33b149567cae946b07a4faf0ed6110014c043cbe89`). It depicts **unwrapped 3D UV albedo islands**, including scattered skin, lavender garment, hair and accessories. The **front concept** is a distinct 1024 × 1536 flattened illustration (SHA-256 `2218bb0a393b90126325e84b3b31028758df91af3d3c1dfbb2a78d9130fecead`). A UV pixel does not encode whether it is front/back, an eyelid or a cheek, its mesh depth, hidden pixels, or how it must deform. The atlas cannot be cut into a believable 2D puppet by rectangular cropping, hue shifts, or a PSD layer exporter.

The correct route is **derive/repaint part-separated 2D character art from the front concept**, using the UV atlas only to match materials and colours. Optional AI separation may produce **candidate** masks on the concept image, not a finished Cubism asset. Artist review and drawing the surfaces that were hidden in the original view remain required. The archive's runnable sample `.moc3` belongs to **Hiyori**, not Lucy. The separate Meshy FBX/GLB is 3D geometry; a 3D UV map is not a 2D Cubism ArtMesh map. The earlier private asset audit and hashed inventory remain in the task evidence directory; the fingerprints above make the source identity checkable without checking the user's private images into Git.

## Rig, motion, export and acceptance gates

1. Create an editable, actually **layered** `lucy.psd`. Do not copy the one-layer albedo PSD into the editor as if it were face/body parts. Artist approves composite, inpainted surfaces and character likeness.
2. Import in [Live2D Cubism Editor](https://docs.live2d.com/en/cubism-editor-manual/psd-import/). Generate and weight ArtMeshes, then parent head, eyes, mouth, limbs, wings, garment and accessories beneath named deformers. Each listed target receives distinct drawable IDs; UV coordinates are generated from the **new art**, not reused from the Meshy atlas or Miara/Hiyori rig.
3. Author default, ±X/Y/Z head poses, blinks/gaze, brows, vowels/smile, subtle chest/shoulder breath, wing and cloth physics; tune geometry in editor at 1× and target-size renders. Preview actual edges across extreme poses and after physics settle. Check `Param*` ranges against the exported rig, never assume Miara's values fit Lucy.
4. Make named `NEUTRAL`, `Smile`, `PHOTO_Awe` (only if the character's actual face looks coherent), idle/breath and a short gesture motion. The previous generated `PHOTO_Awe.exp3.json` is **only a parameter handoff**, not a Lucy-verified expression.
5. Export Lucy-owned `lucy.model3.json`, `lucy.moc3`, textures, expressions, motions, physics/pose/CDI if referenced; include the source `.cmo3` and attribution in the **private authoring handoff**. `model3.json` references are local relative paths. Do not distribute someone else's sample `.moc3` under Lucy's name.
6. Run the structural interchange gate (below), then independently load and inspect the actual model in both AIRI and isolated DeltEcho Electron. Test expressions, motion, resize, disposal/model switch, privacy/permission boundary, and daemon on/off. An AIRI ZIP validation is **not** proof that either runtime renders correctly.

## AIRI integration: actual scoped contract

At AIRI commit [`91953f0`](https://github.com/moeru-ai/airi/blob/91953f0380bc9dca6a9d4082b91510aa4e030559/packages/stage-ui-live2d/src/utils/live2d-zip-loader.ts), its `@proj-airi/stage-ui-live2d` Vue stage uses `pixi-live2d-display/cubism4` and JSZip. `ZipLoader.createSettings` searches archive entries for `.model3.json`, resolves referenced resources relative to that file, and extracts expression/CDI metadata. A **single nested `lucy/` root** with one Lucy-owned settings file and its referenced resources is the explicit interoperability seam. [AIRI's own importer tests](https://github.com/moeru-ai/airi/blob/91953f0380bc9dca6a9d4082b91510aa4e030559/packages/stage-ui-live2d/src/utils/live2d-zip-loader.test.ts) exercise nested settings paths and relative resources. We **do not embed its Vue stage** in DeltEcho React/Electron, copy its user-data stores, start a second daemon, or share cognitive authority.

The render-independent [`@proj-airi/model-driver-magic-live2d`](https://github.com/moeru-ai/airi/tree/91953f0380bc9dca6a9d4082b91510aa4e030559/packages/model-driver-magic-live2d) driver is currently `private: true` and was **not available on npm** when checked. Do not claim it is installed. Its normalized pose/target interface may be adapted in a separately tested future step, with ownership/release arbitration that cannot overwrite authoritative DTE daemon cues or audio lip-sync. The user-owned [`ReZorg/dtecho-nakama-airi`](https://github.com/ReZorg/dtecho-nakama-airi) was checked for useful components; its React canvas uses a Miara CDN model and fixed endocrine mappings, not an exported Lucy model or reusable AIRI stage. No code was copied from it, and no canned thought templates were introduced into DTE.

Run from the repository root **only after a real Lucy export exists**:

```bash
python3 scripts/cubism_airi_interchange.py validate packages/frontend/static/models/lucy --identity lucy
python3 scripts/cubism_airi_interchange.py package packages/frontend/static/models/lucy \
  --identity lucy --output /path/outside/repo/lucy-airi.zip
```

The stdlib tool rejects wrong-named directories/model/MOC, missing MOC/PNG/expressions/motions, extra sample MOCs, traversal/symlink references, oversized resources and output overwrite. It verifies the MOC3 and PNG **signatures**, JSON parseability, referenced resources, nested ZIP paths, integrity and SHA-256. **It does not decode MOC3, validate actual deformation, check licences, or install a character in DeltEcho.** A test fixture has deliberately synthetic `MOC3`/PNG signatures and is **not** a runtime asset. Local test: `python3 -m unittest discover -s scripts -p 'test_cubism_airi_interchange.py' -v`.

An isolated follow-up smoke installed AIRI's upstream loader source at the pinned commit with its own JSZip/Pixi dependencies, then called **the actual `ZipLoader.createSettings` and `ZipLoader.unzip`** on a locally exported, integrity-checked **Miara** ZIP. It resolved `miara/miara_pro_t03.model3.json`, `miara/miara_pro_t03.moc3`, and the 4096px texture; reported **19 runtime resources**, extracted CDI metadata and **13 expression files**. This is direct evidence of AIRI ZIP-loader **structural compatibility** for an existing model, not AIRI stage rendering, a Lucy package, or a licence to distribute Miara's assets. The temporary ZIP was not committed. An artist-signed finished Lucy export and real AIRI/Electron renders remain separate gates.

## PR #70 daemon startup review

The previous desktop change [PR #70](https://github.com/o9nn/deltecho-chat/pull/70) remains **open**. The original raw ESM daemon entry (`dist/bin/daemon.js`) failed on workspace directory imports; the package now builds an esbuild `dist/bin/daemon.mjs` and `start`/`dev`/CLI use that bundle. `DEEP_TREE_ECHO_IPC_PATH` is read from the daemon env, plumbed through `OrchestratorConfig` to `IPCServer`, and matched by Electron's optional **read-only** local broker. `DEEP_TREE_ECHO_ENABLE_AUTONOMY` defaults true but can be disabled for a private IPC-only smoke. The frontend avatar polls the bridge without requiring a local browser cognitive orchestrator; lost lease clears authority-dependent visual state. The earlier direct Electron test observed this in the committed mounted avatar, not just a mock.

The subsequent PR #70 fix [`eb191f38`](https://github.com/o9nn/deltecho-chat/pull/70/commits/eb191f38) changed `prepareUnixSocket`: refuse non-socket occupants; connect-probe an existing socket; only `ECONNREFUSED` proves stale; timeouts and all other errors fail closed; re-check `dev`/`ino` before unlink. Tests added a private absolute socket, non-socket sentinel, live-second-daemon refusal, and **real SIGKILL child** stale-socket recovery. Focused IPC suite passed **18 tests**; project-wide `pnpm check`, `pnpm test`, Electron build and local CI-mode E2E **44 passed / 26 skipped**; all eight PR checks passed in the prior review. This is a valuable accidental-takeover fix, not an authentication mechanism.

**Residual limitation found in review:** shutdown still calls `server.close()` and then unlinks any `activeSocketPath` that exists. On Node 22/Linux, `net.Server.close()` itself removes the **pathname**, not a protected inode: a controlled probe where an already-bound socket was renamed and a sentinel regular file put at its old name showed that `server.close()` removed the sentinel. Thus a hostile local actor able to replace pathnames in the private socket directory can still race teardown; adding an `lstat` check _after_ close would be too late. Do not claim adversarial pathname-race safety from PR #70. Restrict the parent directory to the daemon user (mode 0700), use a private endpoint, do not place it in a shared writable directory for high-assurance deployments, and separately design kernel-level/broker ownership if stronger local threat resistance is required. This plan deliberately leaves PR #70 code untouched; it records the limitation instead of introducing an unverified workaround.
